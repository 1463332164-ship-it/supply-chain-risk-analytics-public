# 模拟数据、指标与解释边界

全部输入为自建模拟数据，不对应任何真实企业。默认种子 20261018，快照日 2026-10-17；30 个 SKU、3 个仓库，每组合 180 天连续需求。需求表 16,200 行、库存快照 90 行、采购订单 540 行。

## 数据契约

CSV 使用 UTF-8，默认生成器写入 BOM；字段顺序严格校验。日期为 ISO 8601，数量为非负整数，金额单位 CNY，`data_origin` 必须为 `synthetic`。采购数量和交期必须为正数。缺失日期不会自动填零，非法数值、主键重复、外键和日期异常会被拒绝。

| 文件 | 主键 | 字段 |
|---|---|---|
| `demand.csv` | date、sku、warehouse | date、sku、warehouse、demand_units、data_origin |
| `inventory.csv` | sku、warehouse | as_of、sku、warehouse、on_hand、backlog、lead_days、safety_days、unit_cost_cny、data_origin |
| `orders.csv` | order_id | order_id、sku、warehouse、supplier、order_date、promised_date、expected_date、received_date、qty、data_origin |

`on_hand` 是快照现货，`backlog` 是既有积压，`lead_days` 是新增采购交期，`safety_days` 是启发式缓冲天数。`promised_date` 是承诺全量收货日，`expected_date` 是当前预计全量收货日，空的 `received_date` 表示未收货。

模拟需求不等于实际销量。生成器包含周周期、部分 SKU 末段增长和低频需求；库存与订单独立生成，不是从历史入出库流水滚动形成，未证明历史库存守恒。当前模型不包含部分收货、取消、退货或多次发运，不能直接接入真实企业数据并沿用这些假设。

## 预测回测

三条基线：Naive 重复最后一天，SeasonalNaive7 重复最近一周，MA28 重复最近 28 天均值。按全局汇总验证 MAE 选一条模型，不按 SKU 分别选最优模型。

以零开始的 180 天序列索引说明：初始训练为 0–123；验证预测 124–151，起点 124、131、138、145；独立测试预测 152–179，起点 152、159、166、173。每个起点仅使用此前历史，预测 7 天；每模型每阶段 90×28=2,520 个预测点。测试段后续起点可使用此前已实现的测试观测，这是滚动回测；测试段不参与选模。库存预测在快照时使用全部已知 180 天需求。

| 指标 | 定义 | 边界 |
|---|---|---|
| MAE | Σ绝对误差 / 预测点数 | 件／日／组合 |
| WAPE | Σ绝对误差 / Σ实际需求 | 分母为零返回 null，大销量权重更高 |
| Bias | Σ(预测−实际) / Σ实际 | 正值高估，零分母返回 null |

基准选择 seasonal7；模拟生成器自带周周期，不能由此宣称该模型在真实业务普遍最优。

## 逐日库存与补货

令场景延后天数为 d，输入交期为 L，则观察窗口 H=L+d+7。未来预测需求乘场景需求倍率。只有未收货且原预计到货日在快照之后的订单进入未来到货日历，再延后 d 天；已过期 ETA 不擅自视为次日到货。

```text
B0 = on_hand - backlog
Bt = B(t-1) + 当日有效预计到货 - 当日预测需求
首次缺口日 = 最早满足 Bt < 0 的 t（含第 0 天）；不存在则为 null
最大净缺口 = max(0, -min(B0, ..., BH))
日均预测 = 窗口预测需求合计 / H
安全缓冲 = safety_days × 日均预测
建议补货量 = max(0, ceil(窗口需求合计 + 安全缓冲 - on_hand + backlog - 窗口有效到货合计))
建议采购额 = 建议补货量 × unit_cost_cny
覆盖天数 = on_hand / 日均预测；日均预测为零时为 null
```

到货在日初可用，需求在日末消耗。余额允许为负，表示模型净缺口，不是负实物库存；没有销量截断或失销机制。最大净缺口不是每日缺口累加，也不是实际失销量。各组合峰值相加不代表同一时点的全网缺口。

补货依据窗口总量及安全缓冲，不能保证补货及时弥补前段缺口；它没有进入图表作为实际到货。后期大量到货可能使补货建议为 0，前期仍存在短缺。零单价也可产生“建议量大于 0、采购额为 0”。采购额不表示降本收益。

展示依据 `first_shortage_day != null` 与 `reorder_suggestion_units > 0` 独立区分四种状态。基准有缺口且建议补货 17 组、有缺口但建议为 0 共 0 组、无缺口但建议补货 4 组、两者均无 69 组。缺口日 0 是快照已有缺口，null 是窗口内无缺口；均不应替换为含糊的空白。

逐日输出需求与余额保留四位小数，金额两位小数；缺口判断使用舍入前数值，因此极小负余额可能显示为 0，后台首次缺口标记仍有效。HTML 读取 `time_path`，不重新预测或修改结果。第 0 天由现货减积压展示，当日需求与到货为不适用；日期按 UTC 加自然日。

## 采购交付与证据

OTD 的分母为快照前最近 28 天（含首尾）承诺到期的订单；分子为实际全量收货日不晚于承诺日的订单。到期但未收货仍在分母，无到期订单返回 null。基准为 171/450=38%；这不是实际供应商表现，也不是 OTIF。

“延期未收订单”满足未收货且承诺日在快照之前；当天到期不计入已延期，但可能影响 OTD。覆盖高于 45 天是固定演示阈值，不直接认定呆滞。对于同一库存组合，程序优先记录预计缺口，仅无缺口时才判断覆盖过高。

证据保留 ID、类型、优先级、SKU、仓库、原值、来源与解释。来源行含 CSV 表头偏移，可沿库存行、需求序列及订单追溯。台账包含全部程序识别的记录；AI 包只从三类证据各取前三项，不是全面 AI 审核或最优风险排序。
