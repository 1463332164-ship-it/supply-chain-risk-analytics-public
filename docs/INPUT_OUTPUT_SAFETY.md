# 输入快照与输出安全

本文中的“发布”指把本地完整临时产物变为正式输出目录，不表示 GitHub 发布。实现位于 `scai/data.py`、`scai/output.py`、`scai/artifacts.py` 和 CLI 入口；这里描述当前行为与适用边界，不依赖私人审核或本机历史档案。

## 同一份字节用于计算和指纹

`read_snapshot()` 捕获 demand、inventory、orders 三张 CSV 的原始字节，放入不可变快照及只读映射。`load_snapshot()` 从这些字节解析并校验；分析结果的输入指纹也只从同一字节计算，不在分析结束后重新读取磁盘内容来绑定结果。

输入摘要保持原契约：按 demand、inventory、orders 顺序，向 SHA-256 依次写入表名 UTF-8 字节和相应 CSV 原始字节，包含 BOM 与换行。`provenance.json` 和额外文件不在此输入指纹中；不要把来源说明误认为被该摘要认证。`.gitattributes` 的 `*.csv -text` 用于防止 Git 换行转换改变参与哈希的 CSV。

捕获前后比较文件身份、大小和时间戳等状态，并复读字节比较。CLI 分析完成后和正式目录发布前再次检查；观察到输入变化就拒绝该次运行。无论外部修改是否逃过观察，计算与绑定摘要都来源于同一快照，而不是不同时间的两次读取。

## 多文件一致性的范围

三张表不是在文件系统的一次事务中读取。这些观察点能发现普通并发保存，但不能证明外部生产者同时提交了三张表，也不保证发现恶意恢复内容及元数据的 ABA 操作。需要跨文件事务时，应由生产者提供已经完成的稳定版本目录。

最后一次观察后，外部进程仍可能修改输入。结果即使成功发布，其摘要也仍代表捕获时的旧字节，不能冒称对应新输入；后续 `verify_run` 会拒绝与不同 CSV 指纹混用。运行包未包含原始三张 CSV，长期复现需另行保存匹配的输入版本。哈希证明内容对应关系，不证明真实性或身份。

## 拒绝覆盖与整目录发布

所有 CLI 输出都要求明确指定新的 `--out`。已有文件、已有目录（含空目录）均拒绝，没有 `--force`。输入与输出相同或互为父子目录会被拒绝；当前存在的路径组件中的符号链接、Windows junction/reparse point 也会被拒绝。Windows 大小写别名及规范化后的路径参与冲突判断。

`generate` 在暂存目录构建完整模拟数据并校验；`analyze` 在输入校验后构建 results、业务 CSV、packet、HTML 及 manifest。输出构建在目标同级的私有临时目录中完成，随后重查目标、父目录身份和适用的输入状态，再执行一次禁止替换目标的目录重命名。

目标若在构建期间或最后一次检查后被其他程序创建，发布失败，不覆盖对方内容。正常异常处理只清理本次暂存产物，不修改旧输入或旧输出。这里依靠整目录重命名，不能将其描述为逐文件写入的整体事务。

| 平台 | 排他发布接口 | 本机验证范围 |
|---|---|---|
| Windows | `os.rename`，已存在目标时拒绝 | 在 Windows 本机执行了路径、覆盖、失败及竞态测试 |
| Linux | `renameat2(RENAME_NOREPLACE)` | 参数及失败分支模拟测试；未在 Linux 实机执行 |
| macOS | `renamex_np(RENAME_EXCL)` | 参数及失败分支模拟测试；未在 macOS 实机执行 |

不支持排他接口的系统或文件系统会失败，不退回可替换空目录的普通 POSIX rename。Windows junction 拒绝路径有真实目录别名测试；符号链接元数据分支有模拟测试，不宣称已完成真实 Windows symlink 创建验收。

## 剩余局限

- 父目录应为可信的本地目录；没有对抗恶意进程在检查间隙替换路径的保证。
- 没有网络文件系统事务、断电持久性或进程强制终止恢复保证。普通失败可能留下新建的空父目录；强制中止或清理失败也可能留下临时目录，不应视为正式运行。
- 正式产物发布后仍可能被外部修改，需继续校验 manifest；摘要不是数字签名，也不抵御协调修改产物及摘要。
- `audit_scenarios.py` 和 `verify.py` 是多次运行与报告的组合，不是整个实验的一次事务；失败时会保留诊断，不应只凭目录存在判断成功。
- AI 校验会核验运行包与实际输入；审核记录不会自动升级、认证审核人或证明业务执行。

## 运行包契约与测试

`verify_run()` 要求 manifest 包含 `results.json`、`forecast_backtest.csv`、`inventory_risks.csv`、`exceptions.csv`、`ai_packet.json`、`dashboard.html` 六个输出的 SHA-256，同时校验实际 CSV、情景参数及从完整结果重建的 packet。`ai_prompt.txt` 不在这六个必需输出中。

`examples/showcase/` 是独立 HTML 演示集合；`showcase_metadata.json` 记录来源、参数与摘要，不是运行 manifest，不能作为 `validate-ai --run` 的完整输入。历史基准夹具须保留匹配的 HTML、CSV、JSON 和 manifest，不能只换页面。

`tests/test_input_output_safety.py` 覆盖逐表读取、解析、分析、哈希、渲染期间的输入修改，最后观察点之后的摘要一致性，以及覆盖、空目录、路径重叠、写入失败、竞态和新目录端到端流程。`tests/test_release_safety.py` 覆盖运行包篡改、情景/输入混用和审核输出保护。实际执行统计及未验证项目见 [README](../README.md#测试与验证范围)。
